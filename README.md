### Relatório Técnico

#### Descrição da Solução

A solução processa dados acadêmicos de uma turma em Haskell. O tipo `Aluno` armazena nome, notas A1 e A2 e número de faltas. O tipo algébrico `Status` limita a situação aos valores `Aprovado` e `Reprovado`. O tipo `Resultado` armazena o nome, a nota final, a frequência e a situação calculada.

A função `avaliarAluno` soma as duas notas, calcula a frequência considerando uma carga horária de 60 horas e aplica as regras acadêmicas. O aluno é aprovado quando possui nota final igual ou superior a 6,0 e frequência igual ou superior a 75%. Cada falta representa uma hora de ausência.

O pipeline funcional utiliza:

- `map` para transformar cada `Aluno` em um `Resultado`;
- `filter` para separar aprovados e reprovados;
- `foldl` para somar notas e frequências e, depois, calcular as médias;
- `arredondarUmaCasa` para apresentar números com uma casa decimal;
- `formatarLinhaAluno` para centralizar a montagem das linhas do relatório e evitar repetição de código.

As funções de média tratam explicitamente a lista vazia, retornando `0.0` para evitar divisão por zero.

#### Análise Comparativa

A solução em Haskell foi comparada com uma abordagem equivalente em Python escrita no estilo imperativo. Haskell descreve as transformações que devem ser aplicadas aos dados, enquanto Python explicita a sequência de instruções, os laços, as condições, as inserções em listas e a atualização dos acumuladores.

#### 1. Sintaxe

Em Haskell, a transformação de toda a lista é expressa diretamente com `map`:

```haskell
resultados = map avaliarAluno alunos
```

Em Python imperativo, seria necessário criar uma lista vazia, percorrer os alunos e inserir cada resultado:

```python
resultados = []

for aluno in alunos:
    resultados.append(avaliar_aluno(aluno))
```

A separação dos estudantes usa `filter` em Haskell, enquanto uma implementação imperativa utiliza `for`, `if` e `append`. A soma feita por `foldl` corresponde a um laço que atualiza uma variável acumuladora em Python.

#### 2. Semântica

Haskell possui tipagem estática com inferência de tipos. As assinaturas são verificadas antes da execução e o tipo `Status` admite somente `Aprovado` ou `Reprovado`. Python possui tipagem dinâmica e suas anotações não oferecem, por padrão, as mesmas garantias do compilador Haskell.

Em Haskell, os valores são imutáveis e as transformações produzem novos valores. Em Python, atribuições vinculam nomes a objetos e listas podem ser modificadas. A unificação participa da inferência e compatibilização de tipos em Haskell, enquanto a atribuição atualiza vinculações em Python.

Haskell possui semântica não estrita, normalmente implementada por avaliação preguiçosa. Python normalmente avalia os argumentos e executa os laços de forma estrita. Haskell também explicita os efeitos de entrada e saída por meio do tipo `IO`, mantendo funções como `avaliarAluno`, `mediaNotas` e `mediaFrequencia` puras.

#### 3. Gerenciamento de Memória

Haskell e Python oferecem gerenciamento automático de memória. Haskell favorece valores imutáveis e pode adiar cálculos devido à avaliação preguiçosa. Python permite a alteração de objetos e listas existentes.

Em listas grandes, `foldl` pode acumular expressões pendentes; nesses casos, `foldl'` pode ser mais apropriado. Na implementação imperativa em Python, operações como `append` modificam uma lista existente. Para este problema, o principal contraste é entre imutabilidade em Haskell e mutabilidade em Python, e não entre coleta automática e liberação manual.

#### 4. Trade-offs

Haskell oferece concisão, segurança de tipos, funções puras, composição e menor risco de alterações inesperadas. O pipeline `map`-`filter`-`foldl` se aproxima da descrição conceitual do problema e reduz o controle manual do estado.

Como desvantagens, Haskell exige familiaridade com funções de ordem superior, composição, tipos algébricos, `IO` e avaliação preguiçosa. Python é mais familiar para quem já conhece `for`, `if`, `append` e acumuladores, além de apresentar a ordem das operações de maneira explícita. Em contrapartida, a versão imperativa exige mais código de controle, permite efeitos colaterais e oferece menos garantias estáticas sem ferramentas adicionais.

#### Resumo da Análise Comparativa

- **Sintaxe:** Haskell utiliza `map`, `filter` e `foldl`; Python imperativo utiliza `for`, `if`, `append` e acumuladores.
- **Semântica:** Haskell possui tipos estáticos com inferência, valores imutáveis e avaliação preguiçosa; Python possui tipos dinâmicos, estruturas mutáveis e avaliação geralmente estrita.
- **Gerenciamento de Memória:** As duas linguagens utilizam gerenciamento automático. Haskell pode manter expressões pendentes devido à avaliação preguiçosa, enquanto Python permite modificar objetos existentes.
- **Trade-offs:** Haskell oferece concisão, segurança e funções puras, mas possui maior curva de aprendizagem. Python é mais familiar e explícito, mas exige mais controle manual e permite mais efeitos colaterais.
